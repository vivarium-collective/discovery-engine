# Visualization Loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Make visualizations a first-class part of the discovery cycle — propose → accept → catch missing/broken → build → refine — by connecting existing machinery, not building a viz subsystem.

**Architecture:** Four new pure primitives + one impure harvest + one injected render hook + strengthened existing functions, persisted as one additive `investigation.yaml: viz_proposals[]` block + normalized fields on `study.yaml: visualizations[]` + the existing `<output>.meta.json` sidecar. Four non-blocking frontier kinds (`viz_broken`, `viz_missing`, `viz_proposed`, `viz_stale`) and two ops (`build_viz`, `refine_viz`). The engine classifies viz *specs* + a figure *inventory* passed in as data (like `evidence_state`/`catalog`); the workbench renders behind a hook; the engine never renders.

**Tech Stack:** Python (discovery_engine), vivarium_workbench (FastAPI + vanilla JS), viva-genesis workspace. Tests: pytest.

**Spec:** `docs/superpowers/specs/2026-10-31-viz-loop-decision.md` — the binding authority. Each task cites its sections; use the exact table values, contracts, and the §4 two-cycle walkthrough from there.

## Global Constraints

- Engine stays general-purpose: **no `vivarium_workbench`/plotly/process-bigraph/workspace-package import in `discovery_engine`** (`tests/test_no_workbench_import.py` + the grep-guard `tests/test_no_domain_coupling.py` stay green). Rendering is an injected capability; the run-command/render-command are templated.
- Derive-first purity: `normalize_entry`, `classify_viz`, the validator, `propose_visualizations` are PURE over `(inv_spec, studies, viz_state, viz_catalog, latest)`. The only new disk read is `viz_inventory`, called by impure callers and passed in. `run_cycle` with no `viz_state` emits ZERO visual records (hermetic fixtures unchanged).
- Never fabricate, never clobber: a render failure leaves the prior figure+meta untouched; an unbuildable entry is reported, never replaced with a stub; no placeholder image is ever written.
- Authored wins: `visualizations[]` is authored; the engine appends an entry only on explicit accept/declare with `origin: {kind: viz_proposal|derived_fix, ref}`; never edits title/config/address silently.
- `visual` records are execution-only → `scientific_judgment` MUST be null (enforced by `validation_record`). Viz kinds are NON-blocking (`_CLOSURE_BLOCKING` unchanged).
- Content-addressed proposal ids; discharge by re-classification; render skip iff `meta.source_run_id == latest.run_id`. No AI attribution in commits. Tests dir is top-level `tests/`.
- Persistence is additive/tolerant-read (`.get`), JSON Schema only at the write boundary (`schemas/investigation-extensions.schema.json`, validated in `persist_cycle`). No study-schema change.

## Review Focus

- **Hermetic purity** — `run_cycle(inv, studies)` with no `viz_state` emits no visual records; the harvest is the only disk read and is outside `run_cycle`. (T2)
- **Clobber safety** — `render_visualizations` on an unbuildable entry does NOT overwrite the existing figure with an error stub; a render failure preserves the prior figure+meta. (T4, T5)
- **No-loop on render** — a render discharges its item only by next-cycle reclassification; skip iff stamped against latest run; a failed render is gated, not retried this advance; `max_runs` counts renders. (T5)
- **Freshness false-stale** — native `requires: []` figures (run the model, not runs.db) use the mtime/`model_version` rule so they aren't mis-flagged stale every run. (T1, T3)
- **Proposal spam/dedupe** — only the 3 triggers, cap 2/study/cycle, content ids, `rejected`/`built` terminal; an already-covered gate proposes nothing. (T8)
- **Catalog-match meaning** — coverage uses the observable NAME (via `covers`/`requires`/`inputs_map`), not just type; type only marks `derivable`. (T8)
