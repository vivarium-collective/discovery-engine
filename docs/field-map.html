12 things worth evaluating — seams, orphans & dead weight›
  • Authored vs computed run on parallel slots. You author executive.verdict_status; the engine writes computed_verdict_status + computed_acceptance beside it and never clobbers yours (per-study: gate_status vs pipeline_gate.gate_evaluator).
  • Three decision objects, two mechanisms in the Decisions tab: authored decisions_needed, engine revision_proposals (approve/reject), engine reconciliation_log (resolve). All write a human verdict the engine reads next cycle — none mutate the model.
  • Orphan write path: proposed_inputs has an accept/decline endpoint but nothing in the SPA renders it.
  • Display dead-ends: at_a_glance, object_of_evaluation, acceptance_criteria ride the payload unrendered (acceptance_criteria still drives the server roll-up).
  • The narrative lens is display-only. "Reading for:" reads narrative.questions and re-scopes client-side; no write-back.
  • Claim identity is scope-sensitive & never persisted. claim_key hashes proposition + scope; content_key is in-memory only.
  • The knowledge layer is read-only audit. shared_claims, knowledge_lift, workspace_profile, evidence_routing write nothing — "a human confirms a share."
  • decision_log is the engine's one new mainline write — appended once per generation output, comment-preserving.
  • discovery.goal/budget are NOT read from YAML (goal = --goal CLI; budget = AutonomyPolicy). Only coverage_dimensions / gates / skill_map are.
  • A big authoring layer is touched by neither system — transition_barriers, candidate_composites, flagship_studies, synthesis, seed blocks. Filter Schema → Instance to see it.
  • Inputs own the broadest free-text surface — /api/prose-edit is whitelisted to exact paths; anything else is rejected server-side.
  • Runs are the engine's only study-side write — reads runs[].outcomes, writes computed_outcomes, preferred over authored.

How to refresh this map›

This is a hand-maintained reference — all of its content lives in this one HTML file (in the repo, docs/field-map.html), with no build step. To bring it up to date after the schemas, the workbench, or the engine change:

  • Field rows are the INV and STUDY arrays in the inline <script>. Each row is {g:group, p:path, t:type, c:what-it-does, w:workbench-role, wn:workbench-note, e:engine-role, en:engine-note}. w ∈ input · display · derived · dead · orphan · none; e ∈ w · r · rw · none.
  • Schema layer is set per field path in the SCH_INV / SCH_STUDY maps: core (.pbg schema) · ext (investigation-extensions.schema.json) · inst (additionalProperties). Use ["core","note"] to add the caveat shown in the drawer.
  • Provenance stamp is the pill row in the header (the two commit SHAs + the date) and the footer scope line — bump these whenever you refresh.
  • Where the facts come from: the workbench side is report_views.build_iset_detail, investigation_graph_views.build_argument_overlay, lifecycle_mutations / models.py / api/app.py, and static/{walkthrough,argument-graph}.js; the engine side is discovery_engine/projection/*, investigation/*, and discover/*. Re-read those for any changed field and update that row's wn / en.
